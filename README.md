## v2.6.1 — APK v1.4.1: fix "Speech failed in this browser" after the rewarded ad (2026-11-11, user order)
The user tested v1.4.0 on his phone: the video ad PLAYS, but after it ends the voice does NOT generate and the app shows "Speech failed in this browser — try another voice or language." He ordered: fix it so it does not fail again — fix EVERYTHING, test thoroughly, report.
- **Root cause (from the code, confirmed by the failure path):** TWO failures stacked. (1) The server TTS call failed on his phone — `generateWithBackend` did a single Worker request with NO retry, so one transient Edge 502 / flaky mobile fetch killed the generation. (2) The fallback then ran `deviceSpeakFlow` (device `speechSynthesis`) unconditionally — in the APK WebView there is no usable device voice, so it failed too and produced the confusing "Speech failed in this browser" message. The Worker itself was verified HEALTHY at the time (curl: 84 of 85 Edge voices HTTP 200 with real audio; rate/pitch regexes accept every value the app produces). Remaining triggers on his phone, ranked: his network/Private DNS (he raised dns.adguard.com) blocking the Worker fetch; his specific text (Edge deterministically rejects some phrases); a transient Edge/Worker failure at that moment; or the Dmitry voice (see below).
- **Retry the server call:** `synthesizeChunk` now retries up to 3 attempts (800 ms, then 1600 ms backoff) on network errors and HTTP 5xx; 4xx is not retried. Each retry is logged in the job status ("Server did not answer — retry 2 of 3…"). `synthesizeToBlob` passes the retry callback through.
- **No broken device fallback in the native app:** when the server fails after retries, the app does NOT fall back to `speechSynthesis` inside Capacitor. Instead it shows the REAL error in the job status (e.g. "could not reach the voice server" for a network failure, or "server error: TTS backend HTTP 502 — {…}" for an HTTP error) plus a red failure card (`#ttsFailBox`) with a "↻ Retry — no new ad needed" button that re-runs the generation from the stored `_lastGen` params. The browser keeps the device-voice fallback (it works there). `generate()` also guards the no-registry-voice case in native (honest "No server voice is available" instead of the device fallback), and `quickSpeak` got the same native rule.
- **DNS warning on voice-server network failure:** when the failure is a fetch/network error (not an HTTP error), the failure card also carries the Private DNS guidance (same wording as the ad-failure card: bilingual, mentions dns.adguard.com, Settings → Network & internet → Private DNS → Off, Try again).
